Network & Static IP

Why set a static IP?

By default, your router gives the Dell a different IP each time it reboots (DHCP). You'd have to find the new IP every time before you can SSH. A static IP pins it to one address so you always know where to connect.

Find Your Current IP

bash
hostname -I # Shows all IPs — find your local one (192.168.x.x) ip addr show # Detailed interface info ip route | grep default # Your gateway (router's IP)

Set Static IP via Netplan

/etc/netplan/00-config.yaml
network:
version: 2
ethernets:
eth0: # change to your interface (ip link)
dhcp4: false
addresses:
- 192.168.1.50/24 # your chosen static IP
routes:
- to: default
via: 192.168.1.1 # your router's IP
nameservers:
addresses: [8.8.8.8, 1.1.1.1]
apply it
sudo chmod 600 /etc/netplan/00-config.yaml # required sudo netplan try # test — auto-reverts if you don't confirm in 120s sudo netplan apply # make permanent

SSH Config Shortcut (on Lenovo)

~/.ssh/config (on Lenovo)
Host dell
HostName 192.168.1.50
User dell
IdentityFile ~/.ssh/id_ed25519
ServerAliveInterval 60

Now you can just type ssh dell instead of the full command.

SSH Setup

Generate Keys (on Lenovo)

Lenovo terminal
ssh-keygen -t ed25519 -C "lenovo-to-dell" ssh-copy-id dell@192.168.1.50 # copies public key to server ssh dell # should log in without password

Harden sshd_config (on Dell)

/etc/ssh/sshd_config
PasswordAuthentication no # keys only — AFTER you've set up key auth PermitRootLogin no PubkeyAuthentication yes X11Forwarding no MaxAuthTries 3 AllowUsers dell # only allow this user to SSH in
apply
sudo sshd -t # test config (no restart) — fix errors first! sudo systemctl restart ssh

Lid Close Fix (So Server Doesn't Suspend)

/etc/systemd/logind.conf
# Edit /etc/systemd/logind.conf — find and change: HandleLidSwitch=ignore HandleLidSwitchExternalPower=ignore
# Then apply: sudo systemctl restart systemd-logind

Access Syncthing UI via SSH Tunnel (from Lenovo)

Why a tunnel?

Syncthing's web UI listens on 127.0.0.1:8384 — only accessible from the Dell itself. To open it on your Lenovo, you create an SSH tunnel that forwards your local port 8384 to the server's localhost:8384 through the encrypted SSH connection.

Lenovo terminal
# Opens tunnel AND a shell — visit http://localhost:8384 ssh -L 8384:localhost:8384 dell@192.168.1.50
# Background tunnel — no shell, just the tunnel ssh -N -f -L 8384:localhost:8384 dell@192.168.1.50

1. Create the Bot (BotFather)

1
Open Telegram → search @BotFather

Message it: /newbot. Give it a name and username (must end in "bot").

2
Copy the API token

BotFather gives you a token like 7234567890:AAF.... Save this.

3
Get your Chat ID

Message your new bot anything. Then visit:
https://api.telegram.org/bot<TOKEN>/getUpdates
Find "id" inside "chat" — that's your chat ID.

4
Save values on the server
bash
echo "BOT_TOKEN=7234567890:AAF..." >> ~/.bashrc echo "CHAT_ID=123456789" >> ~/.bashrc source ~/.bashrc

2. Core notify.sh Script

/home/dell/scripts/notify.sh
#!/bin/bash # Core Telegram notification — call with: notify.sh "message" BOT_TOKEN="${BOT_TOKEN}" CHAT_ID="${CHAT_ID}"
MESSAGE="$1" if [ -z "$MESSAGE" ]; then echo "Usage: notify.sh <message>"; exit 1 fi
curl -s -X POST \
"https://api.telegram.org/bot${BOT_TOKEN}/sendMessage" \
-d chat_id="${CHAT_ID}" \
-d text="${MESSAGE}" \
-d parse_mode="HTML" > /dev/null
echo "[$(date)] Sent: $MESSAGE" >> /var/log/telegram-bot.log

3. Boot Notification Service

/etc/systemd/system/telegram-boot.service
[Unit] Description=Telegram Boot Notification After=network-online.target Wants=network-online.target
[Service] Type=oneshot User=dell EnvironmentFile=/home/dell/.config/telegram.env ExecStart=/home/dell/scripts/notify.sh "🟢 Dell server is up!"
[Install] WantedBy=multi-user.target
enable it
sudo systemctl daemon-reload sudo systemctl enable telegram-boot sudo systemctl start telegram-boot # sends test message

4. Disk Alert Script

/home/dell/scripts/disk-alert.sh
#!/bin/bash THRESHOLD=80 USAGE=$(df / | awk "NR==2 {print \$5}" | tr -d "%") if [ "$USAGE" -ge "$THRESHOLD" ]; then /home/dell/scripts/notify.sh "⚠️ Disk alert! Root at ${USAGE}%" fi

5. Daily Health Report

/home/dell/scripts/health.sh
#!/bin/bash DISK=$(df -h / | awk 'NR==2 {print $5}') MEM=$(free -h | awk '/Mem:/ {print $3"/"$2}') UPTIME=$(uptime -p) LOAD=$(uptime | awk -F"load average:" '{print $2}')
/home/dell/scripts/notify.sh "📊 Daily Health 🗄 Disk: ${DISK} 🧠 RAM: ${MEM} ⏱ Uptime: ${UPTIME} 📈 Load:${LOAD}"

Firewall (UFW)

Current Open Ports

PortProtocolServiceWhy it's open
22TCPOpenSSHRemote access from Lenovo & Android
22000TCP/UDPSyncthingDevice sync protocol
21027UDPSyncthing discoveryLocal device discovery
UFW commands
sudo ufw status verbose # full status + rules sudo ufw allow 22 # open SSH sudo ufw allow 22000 # Syncthing sudo ufw allow 21027/udp # Syncthing discovery sudo ufw deny 80 # block port 80 sudo ufw delete allow 80 # remove a rule sudo ufw enable # turn on firewall
🔴
Always sudo ufw allow 22 BEFORE sudo ufw enable. If you enable UFW without allowing SSH, you'll lock yourself out. If that happens, you'll need physical access to the Dell.

Fail2Ban

Fail2Ban management
sudo fail2ban-client status # overview sudo fail2ban-client status sshd # SSH jail details sudo fail2ban-client set sshd unbanip 1.2.3.4 # unban an IP cat /etc/fail2ban/jail.local # your config journalctl -u fail2ban -f # live logs

Recommended jail.local

/etc/fail2ban/jail.local
[DEFAULT] bantime = 1h findtime = 10m maxretry = 5 ignoreip = 127.0.0.1/8 192.168.1.0/24 # never ban local network
[sshd] enabled = true port = 22 logpath = /var/log/auth.log maxretry = 3 # 3 fails → ban bantime = 24h # ban for 24 hours

Backups

ℹ️
3-2-1 rule: 3 copies of data, on 2 different media, 1 offsite. Even for a home server — hard drives fail. Syncthing already gives you multiple copies across devices, which is great.
/home/dell/scripts/backup.sh
#!/bin/bash set -e BACKUP_DIR="/mnt/backup" SOURCE_DIRS="/home/dell /etc" DATE=$(date +%Y-%m-%d) FILE="${BACKUP_DIR}/backup-${DATE}.tar.gz"
# Clean backups older than 14 days find "$BACKUP_DIR" -name "backup-*.tar.gz" -mtime +14 -delete
# Create backup tar -czf "$FILE" $SOURCE_DIRS 2>/dev/null
# Notify result SIZE=$(du -sh "$FILE" | cut -f1) /home/dell/scripts/notify.sh "✅ Backup done: ${DATE}\nSize: ${SIZE}"
