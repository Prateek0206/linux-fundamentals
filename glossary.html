04 — Glossary

Linux Jargon
Explained

60+ Linux terms explained in plain English — from "what is root?" to "what is cgroups?". Click any term to expand. Search to filter instantly.

rootThe all-powerful admin account (UID 0)beginner▼
Root is the superuser account on Linux — UID 0 — with unlimited permissions. You should never log in as root daily. Use sudo instead for one-off admin commands. "sudo" = "superuser do". Every time you type sudo, it logs the command for auditing.
Example
sudo apt install nginx # run as root, just this once
sudo whoami # prints "root"
id # shows your UID/GID
terminal / shellThe text interface to your computerbeginner▼
A terminal is the window displaying text. A shell is the program inside it interpreting your commands. When you SSH into your Dell server, you get a bash shell. Common shells: bash (default on Ubuntu), zsh (macOS default, very popular), fish (beginner-friendly), sh (minimal POSIX shell).
Example
echo $SHELL # /bin/bash or /bin/zsh
bash --version # GNU bash, version 5.x
sudoRun a command as root — temporary admin powerbeginner▼
sudo = "superuser do". It runs one command with root privileges. Your user must be in the sudo group. After typing your password, sudo caches it for 15 minutes. Every sudo command is logged in /var/log/auth.log. Use sudo -i for a root shell, but exit it quickly — it's dangerous to work as root.
Example
sudo systemctl restart ssh
sudo -l # what can I sudo?
processA running instance of a program with a PIDbeginner▼
Every running program is a process with a unique PID (Process ID). The kernel tracks CPU usage, memory, and state for every process. Short-lived processes like ls die immediately. Long-running ones like Syncthing and SSH stay alive indefinitely. Process 1 is always systemd — the parent of all others.
Example
ps aux # list all processes
pgrep syncthing # get syncthing's PID
kill -9 1234 # force-kill PID 1234
daemonA background service that runs silently (no terminal)beginner▼
A daemon (pronounced "dee-mon") is a background process with no terminal attached. Names typically end in 'd': sshd, crond, nginx. They start at boot and keep running. Your Telegram bot as a systemd service is a daemon. They're managed by systemd on modern Ubuntu.
Example
systemctl list-units --type=service # all daemons
systemctl status sshd
pathThe address of a file or directory on the filesystembeginner▼
Absolute path: starts from root / — always works from anywhere: /home/dell/scripts/notify.sh. Relative path: from your current directory: scripts/notify.sh. $PATH is a colon-separated list of directories the shell searches when you type a command name.
Example
echo $PATH # /usr/local/bin:/usr/bin:...
which python3 # /usr/bin/python3
permissions (rwx)Who can read, write, or execute a filebeginner▼
Every file has three permission sets: owner, group, others. Each set has r (read=4), w (write=2), x (execute=1). chmod 755 = owner can do everything, group and others can read+exec. chmod 600 = only owner can read/write (for SSH keys and secrets).
Example
ls -la script.sh # -rwxr-xr-x
chmod +x script.sh # make executable
chmod 600 id_ed25519 # secure SSH key
packageA bundle of software files ready to installbeginner▼
A package is an archive containing a program's binaries, config files, man pages, and dependency information. Ubuntu uses .deb packages managed by apt. Arch uses .pkg.tar.zst managed by pacman. The package manager handles installing, upgrading, and removing packages, automatically pulling in dependencies.
Example
sudo apt install htop # installs htop package
apt show nginx # info about nginx package
SSHSecure Shell — encrypted remote access to serversbeginner▼
SSH (Secure Shell) lets you remotely control a computer over a network, securely encrypted. When you're on your Lenovo and run ssh dell@192.168.1.x, you get a shell on the Dell as if you were physically there. SSH uses port 22 by default and can authenticate with passwords or cryptographic keys (much more secure).
Example
ssh dell@192.168.1.50 # connect
ssh-keygen -t ed25519 # generate key pair
ssh-copy-id dell@host # copy key to server
kernelThe core of the OS — bridge between hardware and softwarebeginner▼
The Linux kernel is the lowest-level software — it runs in a privileged "kernel space" and directly manages hardware: CPU scheduling, memory allocation, disk I/O, network, and device drivers. User programs run in "user space" and ask the kernel to do things via system calls. You rarely interact with it directly, but uname -r shows which version you're running.
Example
uname -r # 6.8.0-52-generic
uname -a # full system info
distroA Linux distribution — the kernel bundled with softwarebeginner▼
A Linux distribution (distro) bundles the Linux kernel with a package manager, init system, default software, and community support. The kernel is the same; what differs is philosophy, defaults, and tooling. Ubuntu, Arch, Fedora, Debian are all distros — like different car brands using the same engine.
Example
lsb_release -a # Ubuntu 24.04.2 LTS
cat /etc/os-release
stdout / stderr / stdinStandard output, error, and input streamsbeginner▼
Every process gets three file streams: stdin (FD 0) = input (keyboard), stdout (FD 1) = normal output (your screen), stderr (FD 2) = error output (also screen, but separate). You can redirect them: command > out.txt redirects stdout, command 2> err.txt redirects stderr, command >/dev/null 2>&1 discards everything (used in cron jobs).
Example
ls /nonexistent 2>/dev/null # hide error
echo "log" >> file.txt # append stdout to file
pipe ( | )Send one command's output into anotherbeginner▼
A pipe | connects the stdout of one command to the stdin of the next. This is the Unix philosophy: small tools doing one thing, chained together. Pipes are created in kernel memory (no disk I/O), so they're extremely fast.
Example
ps aux | grep syncthing # filter process list
cat /etc/passwd | wc -l # count users
journalctl -u ssh | tail -20
systemdThe init system — PID 1, manages all servicesintermediate▼
systemd is the first process started by the kernel (PID 1) on modern Linux. It reads unit files (.service, .timer, .socket) and starts services in parallel, much faster than the old SysV init. It also manages logging (journald), network, timers, and mounts. If systemd dies, the whole system crashes.
Example
systemctl status syncthing@dell
journalctl -u sshd -f
systemd-analyze blame # boot time per service
inodeThe internal ID of a file — stores metadata, not the nameintermediate▼
Every file has an inode — a data structure storing: permissions, owner, size, timestamps, and disk block pointers. The filename is just a label pointing to an inode. A disk can run out of inodes before running out of space (millions of tiny files). Hard links are two filenames pointing to the same inode. mv is instant because it just changes the directory entry, not the inode.
Example
ls -i file.txt # show inode number
stat file.txt # full inode info
df -i # inode usage per filesystem
symlinkA shortcut that points to another file or directoryintermediate▼
A symbolic link (symlink) is a special file that contains a path to another file. Unlike hard links, symlinks can cross filesystems and point to directories. If the target is deleted, the symlink becomes "dangling" (broken). ls -la shows symlinks with an arrow: link -> /path/to/target. Many system paths are symlinks (e.g., /bin -> /usr/bin on Ubuntu 22+).
Example
ln -s /home/dell/scripts /scripts # create symlink
ls -la /scripts # shows -> /home/dell/scripts
environment variableNamed values available to all processes in the sessionintermediate▼
Environment variables are key=value pairs available to a process and all its children. They configure program behaviour without hardcoding values. PATH tells bash where to find programs. HOME is your home directory. EDITOR sets your default editor. Set them with export VAR=value in your shell or in ~/.bashrc for persistence.
Example
env # all env variables
export TOKEN=abc123 # set for this session
echo $HOME # /home/dell
cron / crontabTask scheduler — run commands at set timesintermediate▼
cron is a daemon that runs scheduled commands. Each user has a crontab (cron table) listing their scheduled jobs. The time format is: minute hour day month weekday command. Systemd timers are the modern alternative but cron is simpler for most cases.
Example
crontab -e # edit your crontab
0 3 * * * /scripts/backup.sh # 3am daily
@reboot /scripts/start.sh # at every boot
crontab -l # list your cron jobs
firewall / UFWControls which network connections are allowedintermediate▼
A firewall filters network traffic based on rules. On Ubuntu, UFW (Uncomplicated Firewall) wraps iptables with simpler commands. Your Dell server has UFW enabled with ports 22 (SSH), 8384 (Syncthing UI via tunnel), and 22000 (Syncthing sync) open. The underlying system is netfilter in the kernel — iptables and nftables are ways to configure it.
Example
sudo ufw status verbose
sudo ufw allow 22
sudo ufw deny 80
sudo ufw enable
SSH key pairCryptographic keys for passwordless, secure SSH loginintermediate▼
An SSH key pair consists of a private key (stays on your machine, never shared) and a public key (copied to the server's ~/.ssh/authorized_keys). Authentication works: the server sends a challenge, you decrypt it with your private key, the server verifies with your public key. No password ever crosses the network. ed25519 is the current best algorithm.
Example
ssh-keygen -t ed25519 -C "lenovo-to-dell"
ssh-copy-id dell@192.168.1.50
cat ~/.ssh/authorized_keys # on the server
mount / filesystemAttaching a disk/partition to a directory in the treeintermediate▼
Linux has one unified directory tree starting at /. "Mounting" attaches a filesystem (a formatted partition or disk) to a directory (mount point). The root filesystem (/) is always mounted at boot. Filesystems can be ext4, xfs, btrfs, tmpfs, etc. /etc/fstab defines what gets auto-mounted at boot.
Example
mount # show all mounted filesystems
sudo mount /dev/sdb1 /mnt/data
cat /etc/fstab # boot-time mounts
signalAsynchronous notifications sent to processesintermediate▼
Signals are inter-process notifications. SIGTERM (15) = please shut down gracefully. SIGKILL (9) = die immediately, no cleanup. SIGHUP (1) = reload config (used by nginx, sshd). SIGINT (2) = Ctrl+C. Programs can catch and handle most signals. SIGKILL and SIGSTOP cannot be caught — the kernel handles them directly.
Example
kill -15 1234 # graceful stop
kill -9 1234 # force kill
kill -1 1234 # reload config (SIGHUP)
kill -l # list all signals
journalctlsystemd's centralised log viewerintermediate▼
journalctl queries the systemd journal — a binary log store that collects output from all systemd services, kernel messages, and boot logs. Unlike text files in /var/log, it supports structured querying by service, priority, time, and more. Logs persist across reboots (unless configured otherwise).
Example
journalctl -u sshd -f # live SSH logs
journalctl -p err # only errors
journalctl --since "2h ago"
journalctl -b -1 # previous boot's logs
NetplanUbuntu's YAML-based network configuration systemintermediate▼
Netplan is Ubuntu's network configuration tool. You write YAML files in /etc/netplan/ and run sudo netplan apply. It translates to either NetworkManager (desktop) or systemd-networkd (server). Used to set static IPs, configure WiFi, VLANs, etc. Your Dell's static IP config lives here.
Example
cat /etc/netplan/00-config.yaml
sudo netplan apply
sudo netplan try # test with auto-revert
Fail2BanBlocks IPs with too many failed login attemptsintermediate▼
Fail2Ban watches log files for patterns (e.g., "Failed password" in /var/log/auth.log) and dynamically adds firewall rules to block offending IPs after a set number of failures. This prevents brute-force SSH attacks. Jails define which services to monitor and the threshold.
Example
sudo fail2ban-client status sshd
sudo fail2ban-client set sshd unbanip 1.2.3.4
cat /etc/fail2ban/jail.local
exit codeA number every command returns — 0 means successintermediate▼
Every command exits with a code: 0 = success, anything else = failure. Bash scripts use this for logic: command1 && command2 runs command2 only if command1 returns 0. $? holds the last exit code. This is how if statements work in bash — they test exit codes, not booleans.
Example
ls /tmp && echo "exists" # runs if ls succeeds
false || echo "failed" # runs if false fails
echo $? # check last exit code
tmuxTerminal multiplexer — multiple windows in one SSH sessionintermediate▼
tmux lets you run multiple terminal sessions within one SSH connection, and — crucially — keep them alive after you disconnect. Start a tmux session, run a long process, detach (Ctrl+B, D), close SSH, reconnect later, re-attach, and the process is still running. Indispensable for server work.
Example
tmux new -s server # new named session
Ctrl+B, D # detach
tmux attach -t server # reattach later
system call (syscall)How user programs ask the kernel to do thingsadvanced▼
User programs can't directly access hardware — they cross into kernel space via system calls. open(), read(), write(), fork(), exec(), socket(), connect() are all syscalls. The boundary crossing is intentionally expensive (CPU mode switch). strace lets you watch every syscall a process makes in real time — invaluable for debugging.
Example
strace ls 2>&1 | head -30 # watch ls's syscalls
strace -p 1234 # trace running process
strace -c ls # syscall count summary
cgroupsControl groups — limit CPU/memory/IO per process groupadvanced▼
cgroups (control groups) is a kernel feature that limits, accounts for, and isolates resource usage (CPU, memory, disk I/O, network) of process groups. Docker uses cgroups to limit container resources. systemd puts every service in its own cgroup. You can see cgroup info in /sys/fs/cgroup/ and set limits in systemd unit files.
Example
systemd-cgls # show cgroup tree
cat /proc/1234/cgroup # cgroup of a process
systemctl set-property sshd.service MemoryMax=100M
namespaceKernel isolation for processes — the basis of containersadvanced▼
Linux namespaces isolate different system resources per process. Types: PID (own process tree), network (own network stack), mount (own filesystem view), UTS (own hostname), IPC (own shared memory), user (own UIDs). Docker combines namespaces + cgroups + overlay filesystems to create containers — lightweight "virtual machines" sharing the host kernel.
Example
lsns # list all namespaces
unshare --pid bash # run bash in new PID namespace
ip netns list # network namespaces
iptables / nftablesThe kernel's packet filtering frameworkadvanced▼
iptables (and its successor nftables) configures the kernel's netfilter packet filtering. UFW is a wrapper around iptables. Rules are organized in chains (INPUT, OUTPUT, FORWARD) and tables (filter, nat, mangle). nftables is faster and more unified, replacing iptables in newer systems. Understanding this is essential for advanced networking and container networking.
Example
sudo iptables -L -n -v # list all rules
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo nft list ruleset # nftables equivalent
LVMLogical Volume Manager — flexible disk managementadvanced▼
LVM adds a layer between physical disks and filesystems. Physical Volumes (PVs) → grouped into Volume Groups (VGs) → divided into Logical Volumes (LVs). Benefits: resize volumes online, span multiple disks, snapshots for backups. Ubuntu installer can set up LVM automatically. Invaluable when your disk fills up — you can add another disk and extend.
Example
pvs / vgs / lvs # display PVs, VGs, LVs
sudo lvextend -L +10G /dev/vg/lv
sudo resize2fs /dev/vg/lv # extend filesystem
ZFSAdvanced filesystem with built-in RAID, compression, snapshotsadvanced▼
ZFS combines the filesystem and volume manager into one. Features: copy-on-write, data integrity checksums, snapshots, clones, transparent compression, and built-in RAID (RAIDZ). Popular for NAS and server storage. On Ubuntu: sudo apt install zfsutils-linux. OpenZFS is the open-source fork used on Linux and FreeBSD.
Example
sudo zpool create mypool /dev/sdb
sudo zfs snapshot mypool/data@backup1
sudo zfs list
zpool status
sysctlKernel parameters you can tune at runtimeadvanced▼
sysctl reads and writes kernel parameters at runtime via /proc/sys/. Used to tune networking (TCP buffer sizes, BBR congestion control), memory (swappiness), and security (IP forwarding for routing). Persistent settings go in /etc/sysctl.conf or /etc/sysctl.d/.
Example
sysctl -a | grep swappiness
sudo sysctl -w vm.swappiness=10
sudo sysctl -w net.ipv4.ip_forward=1 # enable routing
eBPFRun sandboxed programs inside the kernel for tracing and networkingadvanced▼
eBPF (extended Berkeley Packet Filter) lets you run sandboxed programs inside the Linux kernel without changing kernel source or loading kernel modules. Used for ultra-low-overhead observability (bpftrace, bcc), networking (Cilium, XDP), and security (seccomp, Falco). Considered the most significant Linux innovation of the decade.
Example
sudo apt install bpftrace
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat { printf("%s\n", comm); }'
# prints every program opening a file
POSIXThe standard that makes shell scripts portable across Unix systemsadvanced▼
POSIX (Portable Operating System Interface) is a family of IEEE standards defining what a Unix-like OS must provide. A POSIX-compliant script using #!/bin/sh will run on Linux, macOS, BSD, and AIX. Bash has many non-POSIX extensions (arrays, [[ ]], process substitution). When writing portable scripts, stick to POSIX sh. When writing scripts for your specific server, bash extensions are fine.
Example
#!/bin/sh # POSIX - portable everywhere
#!/bin/bash # bash-only features OK
WireGuardModern, simple VPN built into the Linux kerneladvanced▼
WireGuard is a modern VPN protocol built into the Linux kernel since 5.6. It's dramatically simpler than OpenVPN or IPSec (4000 lines vs 400,000). It uses state-of-the-art cryptography (Curve25519, ChaCha20, Poly1305) and is very fast. Tailscale (which you might use for remote server access) is built on top of WireGuard.
Example
sudo apt install wireguard
wg genkey | tee privatekey | wg pubkey > publickey
sudo wg show # show WireGuard status
