Docker

What Docker actually is

Docker packages apps with all their dependencies into containers — lightweight, isolated environments using Linux namespaces + cgroups + overlay filesystems. A container is not a VM (shares the host kernel), but processes inside it think they're alone. This solves "works on my machine" forever.

Install on Ubuntu

bash
curl -fsSL https://get.docker.com | sh sudo usermod -aG docker dell # run docker without sudo newgrp docker

Essential Docker Commands

docker
docker run hello-world # test docker works docker run -d -p 80:80 nginx # nginx in background docker run -it ubuntu bash # interactive Ubuntu shell docker ps # running containers docker ps -a # all (including stopped) docker stop container_id docker logs container_id -f # live container logs docker exec -it container_id bash # shell inside container

Docker Compose

docker-compose.yml
services:
web:
image: nginx
ports: ["80:80"]
volumes: ["./html:/usr/share/nginx/html"]
db:
image: postgres:16
environment:
POSTGRES_PASSWORD: secretpassword
compose commands
docker compose up -d # start all services detached docker compose down # stop and remove docker compose logs -f # follow all service logs docker compose pull # update all images
02

Nginx

Nginx is a web server, reverse proxy, and load balancer. It's extremely fast and efficient — it's likely serving the sites you visit every day. Use it to serve static files, forward traffic to apps, and add SSL.

install + basic commands
sudo apt install nginx sudo systemctl enable nginx nginx -t # ALWAYS test config before reload sudo systemctl reload nginx # apply without downtime

Reverse Proxy Config (most common use)

/etc/nginx/sites-available/myapp
server {
listen 80;
server_name yourdomain.com;

location / {
proxy_pass http://localhost:3000; # your app's port
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
}
}

SSH Tunnels

Three types of SSH tunnel

Local: Forward your local port → remote service (access Syncthing UI). Remote: Forward remote port → your local machine (expose local server to remote). Dynamic: SOCKS proxy through SSH (route all traffic via server).

SSH tunnels
# LOCAL: access Syncthing UI on Lenovo ssh -L 8384:localhost:8384 dell@192.168.1.50 # → visit http://localhost:8384
# Background tunnel, no shell ssh -N -f -L 8384:localhost:8384 dell@192.168.1.50
# REMOTE: expose local port 3000 on remote port 9000 ssh -R 9000:localhost:3000 dell@192.168.1.50
# DYNAMIC SOCKS proxy through Dell ssh -D 1080 -N -f dell@192.168.1.50

WireGuard VPN

WireGuard is a modern VPN built into the Linux kernel. It's faster and simpler than OpenVPN. Great for accessing your Dell server from outside your home network.

WireGuard setup (server)
sudo apt install wireguard
# Generate keys wg genkey | sudo tee /etc/wireguard/private.key sudo chmod 600 /etc/wireguard/private.key sudo cat /etc/wireguard/private.key | wg pubkey | sudo tee /etc/wireguard/public.key
💡
For the easiest WireGuard setup, consider Tailscale — it's WireGuard underneath but handles key exchange, DNS, and NAT traversal automatically. Free for personal use, works great for remote server access.
Tailscale (much simpler)
# Install on Dell curl -fsSL https://tailscale.com/install.sh | sh sudo tailscale up # open URL in browser to login tailscale ip -4 # your Tailscale IP (e.g. 100.x.x.x)
# Now SSH from anywhere (phone, office, etc) ssh dell@100.x.x.x # works even from other networks

iptables Deep Dive

How iptables works

iptables is a userspace tool to configure the kernel's netfilter packet filter. Packets travel through chains (INPUT, OUTPUT, FORWARD) in tables (filter, nat, mangle). Rules are checked in order — first match wins. If no rule matches, the chain's default policy applies (usually ACCEPT or DROP).

iptables
sudo iptables -L -n -v # list all rules + packet counts
# Add rules sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT sudo iptables -P INPUT DROP # default deny — ONLY AFTER allowing SSH!
# Flush (reset to empty) sudo iptables -F

Kernel Tuning (sysctl)

useful sysctl settings
sysctl -a # show all kernel params sysctl vm.swappiness # current swappiness sudo sysctl -w vm.swappiness=10 # set temporarily
# /etc/sysctl.d/99-custom.conf (persistent): vm.swappiness = 10 # less swap (good for SSDs) net.ipv4.ip_forward = 1 # for Docker / routing fs.inotify.max_user_watches = 524288 # Syncthing large dirs
sudo sysctl -p /etc/sysctl.d/99-custom.conf # apply

LVM — Logical Volume Manager

LVM management
pvs # physical volumes vgs # volume groups lvs # logical volumes
# Extend LV by 10G (online — no downtime!) sudo lvextend -L +10G /dev/ubuntu-vg/ubuntu-lv sudo resize2fs /dev/ubuntu-vg/ubuntu-lv # grow filesystem df -h / # verify
